# Конспект 3. Конфиги и проектные инструкции

## Главная идея

Конфиг — это файл с настройками. Он помогает инструментам и ассистенту понимать, как работать в проекте.

## Что такое конфиг

Конфиг не является основной логикой проекта, но влияет на поведение инструментов.

Примеры:

- `.gitignore` — какие файлы Git не должен сохранять.
- `.env.example` — какие переменные окружения нужны проекту.
- `package.json` — команды, зависимости и информация о проекте.
- `.prettierrc` — правила форматирования.
- `.codex/config.toml` — настройки Codex для проекта.
- `AGENTS.md` — постоянные инструкции для Codex.

## Почему это важно для вайбкодинга

Если правила проекта не записаны, ассистент вынужден угадывать. Конфиги и проектные инструкции уменьшают количество повторных объяснений.

## Конфиг и заметка

Заметка отвечает на вопрос: "Что мы знаем?"

Конфиг отвечает на вопрос: "Как здесь работать?"

Для сильного контекста нужны оба вида файлов.

## Минимальные инструкции для ассистента

Хороший файл инструкций содержит:

- цель проекта;
- роль ассистента;
- важные команды;
- правила работы;
- ограничения;
- место, куда сохранять новый контекст.

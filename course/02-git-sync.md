# Обязательная настройка: локальный Git и Obsidian Git

В этом шаге вы подключите Git к личному vault и настроите Obsidian Git. Обязательная цель — получить локальную историю изменений, к которой можно вернуться даже без удалённого репозитория.

Если у вас уже есть подходящий репозиторий и доступ к корпоративному GitLab, после локальной настройки можно дополнительно включить удалённую синхронизацию. Специально создавать заявку на доступ или новый корпоративный репозиторий ради курса не нужно.

Инструкция рассчитана на настольную версию Obsidian. Мобильная синхронизация в курс не входит.

## Что обязательно получится в конце

- папка vault станет локальным Git-репозиторием;
- Git начнёт хранить историю изменений заметок;
- Obsidian Git будет автоматически создавать локальные commit;
- вы проверите, что изменение заметки появилось в истории Git.

## Что зависит от уже имеющегося доступа

Подключение к `gitlab.agimagroup.ru` выполняется только при двух условиях:

1. у вас уже есть доступ к корпоративному GitLab;
2. для вашего vault уже существует подходящий репозиторий либо ответственный сотрудник предоставил его без отдельной заявки в рамках курса.

Если хотя бы одно условие не выполнено, пропустите раздел про GitLab. Модуль всё равно можно завершить по локальной истории Git.

## Безопасность

Никогда не вставляйте в заметки, репозиторий или диалог приватный SSH-ключ, персональный токен GitLab, пароль или содержимое `.env` с реальными секретами.

## 1. Проверка Git

Codex сам проверит, установлен ли Git:

```bash
git --version
```

Если Git не найден, наставник объяснит следующий шаг с учётом вашей рабочей системы. Не переходите дальше, пока команда не покажет версию Git.

## 2. Создание локального Git-репозитория

Codex сначала подтвердит, что работает именно с вашей папкой `my-work/obsidian-vault/`, и только после этого создаст в ней репозиторий:

```bash
git init
git branch -M main
```

Затем Codex проверит имя и email автора Git. Если они не заданы, наставник уточнит эти данные и сохранит их только для этого vault:

```bash
git config user.name "Ваше имя"
git config user.email "ваша_рабочая_почта"
```

Codex создаст первый commit:

```bash
git add .
git commit -m "Initialize Obsidian vault"
```

И сразу проверит результат:

```bash
git log --oneline -5
```

## 3. Установите Obsidian Git

В Obsidian:

1. Откройте **Settings → Community plugins**.
2. Разрешите community plugins, если они отключены.
3. Нажмите **Browse**.
4. Найдите плагин **Git** автора Vinzent.
5. Установите и включите его.

## 4. Настройте локальные commit

Откройте настройки плагина Git и задайте:

- автоматический backup/commit — каждые `5` минут;
- сообщение автоматического commit — `vault: {{date}} — auto-save`;
- отображение статуса Git — включено;
- автоматические pull и push — выключены, пока remote не подключён.

Названия полей могут немного отличаться в разных версиях плагина. Если не находите нужное поле, опишите в текущем диалоге, что видите на экране. Наставник поможет сопоставить настройку по смыслу. Не включайте неизвестные параметры наугад.

## 5. Проверьте обязательный локальный цикл

1. Внесите небольшое осмысленное изменение в заметку проекта.
2. Откройте командную палитру Obsidian.
3. Запустите команду Git для создания backup/commit.
4. Дождитесь завершения без ошибки.
5. Напишите в текущем диалоге «готово». Codex сам проверит локальную историю и состояние vault:

```bash
git log --oneline -5
git status
```

6. Вместе с наставником убедитесь, что новый commit появился в истории.

Этой проверки достаточно для обязательной части модуля.

## 6. Если корпоративный репозиторий уже есть

Не создавайте заявку на доступ специально ради курса. Продолжайте только с репозиторием, который уже предназначен для вашего vault.

Возможны два сценария:

### Репозиторий пустой и создан для этого vault

Скопируйте **Clone with SSH** со страницы репозитория и отправьте адрес в текущий диалог. Не передавайте пароль, токен или приватный SSH-ключ. Codex проверит адрес и добавит remote командами:

```bash
git remote add origin git@gitlab.agimagroup.ru:<ваша-группа>/<ваш-vault>.git
git push -u origin main
```

Пример адреса нельзя использовать дословно: Codex подставит адрес именно вашего репозитория.

### Репозиторий уже содержит vault или другие файлы

Не подключайте его к текущей папке и не отправляйте изменения поверх существующей истории. Сообщите в текущем диалоге, что репозиторий уже содержит файлы. Codex изучит структуру и предложит безопасный сценарий клонирования или переноса заметок.

После успешного подключения remote настройте в Obsidian Git:

- автоматический pull — каждые `5` минут;
- pull при запуске Obsidian — включён;
- push после автоматического commit — включён;
- pull перед push — включён;
- стратегия синхронизации — `rebase`;
- сообщение commit — `vault: {{date}} — auto-sync`.

Проверьте синхронизацию: измените заметку, выполните commit-and-sync и убедитесь, что commit появился в вашем репозитории GitLab.

## Что не попадает в Git

Стартовый vault содержит `.gitignore`, который исключает всю папку `.obsidian` с локальным состоянием интерфейса и настройками плагинов, а также корзину и системные файлы macOS.

Если позже вы решите хранить часть настроек `.obsidian` в Git, сначала проверьте каждый файл на ключи, токены и локальные пути.

## Если возник конфликт

Не удаляйте файлы и не запускайте `git reset --hard`. Остановите автоматическую синхронизацию и сообщите об ошибке в текущем диалоге. Codex сам:

1. покажет `git status`;
2. объяснит, какие версии конфликтуют;
3. поможет сохранить нужное содержимое;
4. проверит результат перед продолжением синхронизации.

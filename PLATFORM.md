# Как загрузить курс на обучающую платформу

Репозиторий можно давать ученикам как скачиваемый архив или как GitHub-ссылку.

Перед публикацией или пушем запустите `bash scripts/check-course.sh`. Проверка остановится, если рабочие шаблоны отличаются от чистого эталона, сохранились старые названия или появились битые локальные ссылки.

## Рекомендуемый сценарий

1. Ученик скачивает репозиторий с GitHub.
2. Открывает папку проекта в Codex.
3. Открывает `START_HERE.md`.
4. Копирует стартовый промпт в ИИ-ассистента.
5. По возможности проходит курс в одной задаче Codex, сохраняя прогресс в файлах.
6. Выполняет задания из `exercises/`.
7. Заполняет `checkpoint.md` из личной копии в `my-work/exercises/`.
8. Обновляет `my-work/student-work/progress.md`.
9. Во втором модуле создаёт локальную Git-историю vault и подтверждает commit через Obsidian Git. Корпоративный remote подключает только при уже имеющемся доступе.

## Важно для подготовки релиза

Не тестируйте прохождение в той же папке, которую будете загружать на GitHub как чистый шаблон. Для проверки сделайте отдельную копию проекта.

Личные ответы и тестовые записи должны храниться только в `my-work/`; эта папка создается командой `bash scripts/start-course.sh` и исключена из Git через `.gitignore`.

## Что приложить на платформе

- Ссылку на GitHub-репозиторий.
- Инструкцию открыть папку проекта в Codex.
- Требование установить Obsidian.
- Требование иметь Git. Доступ к корпоративному GitLab не должен быть обязательным и не должен требовать отдельной заявки ради курса.
- Рекомендацию вести прохождение в одной задаче Codex и восстанавливать прогресс по файлам.
- Описание финального результата: собственный Obsidian vault для накопительного ИИ-контекста с локальной Git-историей и возможностью подключить доступный корпоративный remote.

Готовые тексты для платформы лежат в папке `portal`.

## Конспекты для скачивания

После каждого урока ученику можно выдавать соответствующий файл из папки `handouts`.

## Обязательная активность модуля 2

На платформе вынесите `course/02-git-sync.md` в отдельную обязательную активность между теорией Obsidian и практическим чекпоинтом. Модуль 2 не должен отмечаться завершённым без подтверждения локального commit через Obsidian Git. Подключение к GitLab остаётся условной частью и не влияет на зачёт.

## Проверка результата

Для зачета ученик может загрузить:

- заполненные `checkpoint.md` из `my-work/exercises/`;
- скриншот графа Obsidian;
- подтверждение локального commit из чекпоинта второго модуля;
- 3-5 заметок из своего vault;
- ретроспективу полной ИИ-сессии.
